## Phase Goal

**As an** operator, **I want to** launch the full Kurzly stack with `docker compose up` and see the dashboard load live data from Postgres — configured only via environment variables and with data that survives restarts — **so that** I can trust the self-hosted deployment works end-to-end before enabling real features.

> This plan advances the skeleton: it makes the TDD harness continuously enforced (CI) and documents operator TLS.

<objective>
Close the phase: a CI workflow that runs the whole test suite on every change (D-11, the TDD mandate), and the reverse-proxy/TLS deployment documentation that stands in for wiring a proxy into product code (D-03/D-04). Together these make the harness continuously enforced and give operators the last piece needed to run Kurzly behind their own TLS.

Purpose: TDD is only real if CI enforces it on every change; and self-hosted operators need concrete TLS guidance since Kurzly deliberately ships no bundled proxy.
Output: `.github/workflows/ci.yml` and `docs/deployment/reverse-proxy.md`.
</objective>
