## Phase Goal

**As an** operator, **I want to** launch the full Kurzly stack with `docker compose up` and see the dashboard load live data from Postgres — configured only via environment variables and with data that survives restarts — **so that** I can trust the self-hosted deployment works end-to-end before enabling real features.

> This plan advances the skeleton: it packages everything into the deployable `docker compose up` artifact and proves boot + persistence.

<objective>
Package the single-image build and the production Compose stack (D-01/D-02): a multi-stage Dockerfile that builds the workspace and prunes to a production `app` image serving the API + built SPA, an entrypoint that applies migrations automatically before starting the server (D-05), a two-service `docker-compose.yml` (`app` + `db`) with a named volume + healthcheck-gated startup, a dev-only overlay adding Mailpit (D-10), and the two smoke scripts proving INFRA-01 (zero-manual-step boot) and INFRA-03 (persistence across restart).

Purpose: This is the operator payoff — `docker compose up` and it works, configured entirely via ENV, with durable data. It ties every prior plan into the deployable artifact.
Output: A buildable image, a bootable compose stack, and executable smoke scripts.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator host → container network | Only published ports are reachable from the host; the DB should not be |
| image build → shipped artifact | Secrets or migration behavior baked into the image would be exposed/incorrect |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-15 | Information Disclosure | Secrets baked into the image | high | mitigate | No secrets in the Dockerfile; `.env` is gitignored + dockerignored; `app` reads config only via `env_file`/environment (INFRA-02) |
| T-01-16 | Elevation of Privilege | Postgres port exposed to the host in production | high | mitigate | `docker-compose.yml` publishes only the app port (3000); the DB port is not mapped to the host (D-03) |
| T-01-17 | Denial of Service | Destructive migration on start | high | mitigate | Entrypoint runs `prisma migrate deploy` only (forward-only); never `migrate reset`/`db push --accept-data-loss` in production (Pitfall 4) |
| T-01-18 | Information Disclosure | Mailpit shipped in production | medium | mitigate | Mailpit lives only in `docker-compose.dev.yml`; production compose never references it (D-10) |
</threat_model>
