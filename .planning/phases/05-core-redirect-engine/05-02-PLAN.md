<objective>
Extend the Link model, the single validated write path, and the shared DTOs so users can set a password (D-02, bcrypt), an expiry date (D-03, day granularity), and per-link query forwarding (D-12) on a link — the data foundation the redirect engine and the form UI both consume. All three fields flow through the D-01 single write path (`createLink`/`updateLink`), never a second write site; the password is hashed inside that core and the hash is never exposed in any DTO.

Purpose: The redirect engine (05-05) reads `Link.passwordHash`/`expiresAt`/`forwardQuery`; the form (05-06) writes them. This plan makes the columns real (with the mandatory migration) and proves the no-plaintext-leak DTO contract with tests.
Output: Migrated schema + regenerated client; hashing + new-field persistence in `lib/links.ts`; extended Zod schemas in `routes/links.ts`; extended shared DTOs; green integration tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API (link write) | Untrusted create/update body (may carry a password) |
| API → DB | Hashed credential + expiry persisted |
| DB → DTO/JSON | Response must never carry the hash |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-DTO-LEAK | Information Disclosure | toLinkDto / API responses | high | mitigate | DTO exposes only a derived `passwordProtected` boolean; a test asserts no passwordHash in any response body |
| T-05-PLAINTEXT | Information Disclosure | password handling / logs | high | mitigate | bcryptjs hash at rest (cost from PASSWORD_HASH_COST); never store/compare/log plaintext (D-02) |
| T-05-MASS-ASSIGN | Tampering | link write body | medium | mitigate | Zod allowlist (create/update schemas) — only the named fields cross into createLink/updateLink; passwordHash is never client-settable |
| T-05-2ND-WRITE | Tampering | link persistence | medium | mitigate | All three fields persist ONLY through the D-01 createLink/updateLink core; no second write site introduced |
</threat_model>
