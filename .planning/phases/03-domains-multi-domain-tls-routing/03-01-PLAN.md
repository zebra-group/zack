<objective>
Extend the near-empty Phase-2 Domain model into a full lifecycle entity, apply it to real Postgres via a [BLOCKING] migration, and deliver the first vertical capability: an authenticated admin can register a domain (status "pending", owner membership bootstrapped) and list their own domains through `requireDomainAccess`/`scopedDomainIds`.

Purpose: This is the schema + authorization-bootstrap foundation every other Phase-3 plan builds on (verify, tls-check, frontend all read the extended Domain). It resolves the RESEARCH A1 authz chicken-and-egg gap: no DomainMembership rows exist yet, so creation is gated on an authenticated allowlisted session and atomically creates the owner membership.

Output: extended Prisma schema + migration + generated client, DomainDTO in shared, two new env vars, both rate-limit consts, `domains.ts` with POST/GET wired into `app.ts`, and a real-Postgres integration suite for DOMAIN-01.
</objective>

**As an** admin, **I want to** register one of my own domains/subdomains and see it listed as "DNS pending", **so that** I have a domain record the redirect engine and operator TLS proxy can later resolve against. (Derived from Phase 3 Success Criterion 1 + DOMAIN-01.)
