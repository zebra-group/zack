## Phase Goal (user story)

**As an** operator, **I want** my reverse proxy to ask Kurzly whether a hostname is verified before issuing a TLS certificate, **so that** certificates are issued on-demand only for domains I have actually verified — and a spoofed or unregistered Host is never matched to one of my domains. (Derived from Phase 3 Success Criteria 3 (reformulated per D-01) + 4, DOMAIN-03.)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator proxy → GET /api/tls-check | Untrusted, session-less caller; response decides whether a cert is issued for a hostname |
| incoming Host / X-Forwarded-Host → domain resolution | Spoofable header must never determine which domain is served |

## STRIDE Threat Register (ASVS L1, block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-02 | Spoofing | Host / X-Forwarded-Host → domain resolution | high | mitigate | `resolveActiveDomainByHost` exact-match, lowercased, port-stripped, `status === 'active'` only; deny-by-default on any miss (no wildcard/substring/first-domain) — proven by spoof/partial-host tests. The ask decision reads the `?domain=` param (Caddy SNI), never a raw header. |
| T-03-04 | Information Disclosure | GET /api/tls-check (domain enumeration) | medium | mitigate | Status code only (200/404), empty body in both branches — no target URL, account, or "exists-but-not-active vs unregistered" distinction beyond the code itself. |
| T-03-05b | Denial of Service | GET /api/tls-check (handshake-path abuse) | medium | mitigate | `TLS_CHECK_RATE_LIMIT` (60/min); single indexed `findUnique`, no joins/external calls so latency stays low on the handshake critical path (Pitfall 3). |
</threat_model>
