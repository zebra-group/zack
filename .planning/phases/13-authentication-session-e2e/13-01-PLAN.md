<objective>
Stand up the repo's first mock OIDC Identity Provider as a 4th `docker-compose.e2e.yml` service (`oidc-mock`), wrapping `oidc-provider@9.10.0` in a ~120-line Koa script, and wire the `app` container's `OIDC_ISSUER_URL`/`OIDC_CLIENT_ID`/`OIDC_CLIENT_SECRET` to it. This is the single new piece of infrastructure this phase needs; it unblocks the SSO round-trip (AUTH-E2E-04) and SSO-after-invite merge (AUTH-E2E-05) specs, which cannot exist until a real authorization-code redirect dance is reachable from BOTH the containerized backend (server-to-server discovery/token/userinfo) and the host Playwright browser (the authorization redirect hop).

The mock deliberately solves the dual-reachability problem via a discovery-document rewrite (per 13-RESEARCH.md Pattern 1) rather than `host.docker.internal`/`host-gateway`, which multiple community reports flag as unreliable inside GitHub Actions Ubuntu runners — and this phase's CI job is the merge gate. Enabling OIDC env in the E2E overlay honors D-10-03 (genericOAuth registered only when all three OIDC vars are present) and D-10-06 (the fixed callback path `/api/auth/oauth2/callback/oidc`).

Purpose: Give AUTH-E2E-04/05 a spec-compliant, programmatically-controllable IdP with zero live network egress in CI.
Output: A booting `oidc-mock` service, compose wiring, and a healthcheck so `docker compose up --wait` blocks until the mock's discovery endpoint is live.
</objective>
