## Phase Goal

**As a** dashboard user managing campaign links, **I want to** attach UTM parameters and custom social-preview metadata to a short link and see exactly what the final URL and the social card will look like before I save, **so that** my campaign traffic is attributed correctly and my links preview the way I intend — without Kurzly ever fetching the destination.

> Derived from the ROADMAP Phase 8 `**Goal:**` line into user-story shape (MVP framing), matching the Phase 7 precedent.

<objective>
Make the six new Link fields storable end-to-end: schema + migration, the shared DTO/Input types, the single validated write path (`lib/links.ts`, D-08-06), and the HTTP allowlist (`routes/links.ts`). After this plan a user can create and edit a link carrying UTM parameters and custom OG values through the API, with every value validated to D-08-05's limits and D-08-04's http(s)-only image-URL rule.

Purpose: This is the foundation slice — every other plan in the phase reads these columns.
Output: One additive migration, six nullable columns, six threaded fields, five new typed error codes.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → POST/PATCH /api/links | Authenticated dashboard input crosses into the API and is persisted onto a Link |
| stored ogImageUrl → future consumers | An owner-typed URL is stored and later emitted into HTML (plan 08-02) — it must never be fetched, and never carry a non-http(s) scheme |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-MASS | Tampering | createLinkSchema / updateLinkSchema | high | mitigate | The six fields are explicitly enumerated on the Zod allowlist; the handler reads only `parsed.data`; `lifetimeClicks`/`passwordHash` remain un-allowlisted |
| T-08-SSRF | Information Disclosure | ogImageUrl handling | high | mitigate | Structural: no fetch/request call is added anywhere on the write path for ogImageUrl (D-08-04). Only shape validation. |
| T-08-SCHEME | Tampering | ogImageUrl validation | high | mitigate | `z.url({ protocol: /^https?$/ })` — the same WHATWG-parser-backed idiom `targetUrlSchema` uses; `javascript:`/`data:`/relative values rejected as OG_IMAGE_URL_INVALID |
| T-08-STORAGE | Denial of Service | six new text columns | medium | mitigate | Per-field length caps enforced in `validateLinkInput` before any write (D-08-05); `@fastify/rate-limit` already bounds the create/update endpoints |
| T-08-BYPASS | Elevation of Privilege | write path | medium | mitigate | The six fields are only ever written by `createLink`/`updateLink` (D-08-06 / D-01); no route touches `prisma.link.create|update` directly |
</threat_model>
