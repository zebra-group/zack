## Phase Goal

**As a** Kurzly operator, **I want to** enable optional OIDC/SSO login through environment variables — with the admin screen showing whether it is active and the exact callback URL to register — **so that** my team can sign in through our own identity provider while magic-link keeps working unchanged and SSO-provisioned users never inherit admin.

> Derived from the ROADMAP Phase 10 goal line into user-story shape (MVP framing), matching the Phase 7/8/9 autonomous precedent.

<objective>
Wire better-auth's genericOAuth plugin into createAuth ONLY when OIDC is configured (D-10-03), so magic-link-only installs expose no OAuth endpoints and "magic-link keeps working unchanged" (AUTH-06) is the structural default rather than something tested around. Prove the two headline safety guarantees with automated tests: the OAuth-endpoints-absent-when-unset structural proof (AUTH-06), and the least-privilege provisioning guarantee — an SSO-created user is always accountRole=member with zero DomainMemberships, never Admin, regardless of IdP claims (AUTH-07, D-10-04, ROADMAP success criterion 3).

Uses genericOAuth (D-10-01 — the installed 1.6.23 does not ship an `sso` plugin; genericOAuth's discoveryUrl gives the same issuer-only ergonomics) with no new dependency and no schema migration (D-10-05).
Purpose: this is the security spine of the phase — the two guarantees the morning review exists to check.
Output: the conditional genericOAuth registration in auth.ts and the sso-auth integration suite proving both guarantees.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external IdP → API | The OIDC provider's token/userinfo response (subject, email, and any role/groups claims) is untrusted input crossing into provisioning |
| anonymous client → auth endpoints | /api/auth/oauth2/* is internet-facing; on magic-link-only installs it must not exist at all |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-CLAIM-ELEV | Elevation of Privilege | genericOAuth provisioning | critical | mitigate | no mapProfileToUser maps any IdP claim to accountRole or domain access; accountRole stays input:false with DB default member and zero memberships; proven by the AUTH-07 least-privilege + no-claim-elevation tests (D-10-04) |
| T-10-ENDPOINT-EXPOSURE | Spoofing | /api/auth/oauth2/* on magic-link-only installs | medium | mitigate | conditional registration (D-10-03) — the plugin is absent unless OIDC is configured; proven by the AUTH-06 oauth2-endpoint-404 test |
| T-10-DISCOVERY-TARGET | Information Disclosure | discoveryUrl fetch to {issuer}/.well-known | low | accept | issuer is operator-supplied trusted config (validated as a URL in env.ts, not user input); better-auth fetches only the derived discovery document from that operator-owned issuer — accepted |
| T-10-SSO-SESSION | Spoofing | genericOAuth state/PKCE/session issuance | low | accept | better-auth owns OAuth state, PKCE, and session cookie issuance end-to-end (same posture as magic-link) — no hand-rolled token handling is introduced |
</threat_model>
