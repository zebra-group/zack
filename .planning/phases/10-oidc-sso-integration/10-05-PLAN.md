## Phase Goal

**As a** Kurzly operator, **I want to** enable optional OIDC/SSO login through environment variables — with the admin screen showing whether it is active and the exact callback URL to register — **so that** my team can sign in through our own identity provider while magic-link keeps working unchanged and SSO-provisioned users never inherit admin.

> Derived from the ROADMAP Phase 10 goal line into user-story shape (MVP framing), matching the Phase 7/8/9 autonomous precedent.

<objective>
Build the end-user half of AUTH-06: the conditional "Mit SSO anmelden" affordance on the real login screen (10-UI-SPEC Surface B). It appears only when SSO is active, sits below the always-present magic-link primary button as a secondary action with the locked "oder" divider and the green --ok status dot (UI-10-07/10), and initiates the real better-auth genericOAuth sign-in redirect (UI-10-08 — not the prototype placeholder toast). If the enabled flag cannot be read, the affordance stays hidden (fail-closed) so a broken status fetch never offers a dead SSO path (UI-10-08).

Follows LoginView's existing direct-fetch style (it already calls /api/auth/sign-in/magic-link directly, not through api.ts), so this plan touches no shared api.ts and runs parallel to 10-04.
Purpose: a user can actually start an OIDC login when the operator has enabled it, while magic-link is untouched (AUTH-06).
Output: the LoginView SSO affordance + its tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| status flag → login render | Whether the SSO affordance is offered depends on an unauthenticated status read; a failed read must never falsely offer SSO |
| browser → genericOAuth sign-in | The sign-in initiation hands control to better-auth's OAuth redirect; the callbackURL must stay same-origin |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-FAILOPEN | Spoofing | SSO affordance on status-fetch failure | medium | mitigate | fail-closed — ssoEnabled stays false on any fetch/parse failure, so the button is hidden and no dead SSO path is ever offered; magic-link remains the only visible path (UI-10-08) |
| T-10-OAUTH-REDIRECT | Tampering | genericOAuth sign-in callbackURL | low | mitigate | callbackURL is the same-origin "/"; better-auth owns OAuth state/PKCE and the authorize redirect end-to-end — no hand-built redirect target from untrusted input |
| T-10-COLOR-ONLY | Information Disclosure | green --ok status dot | low | mitigate | the dot is decorative (aria-hidden); the affordance's meaning is carried by the "Mit SSO anmelden" text label, not by color alone (accessibility contract) |
</threat_model>
