## Phase Goal

**As a** team operator, **I want to** sign in to Kurzly with a magic link and land in a themeable dashboard shell whose every domain-scoped action is authorized server-side, **so that** I can manage short links securely on my own infrastructure.

> This plan completes the user-facing slice: the persistent themeable App Shell (UI-01/UI-03), the Dashboard landing + Coming-soon placeholders (D-03), the router auth guard (AUTH-03), and the from-every-page logout (AUTH-04) — the shell later feature phases dock into.

</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vue Router guard → protected routes | Client-side gate is UX only; not a security boundary |
| logout control → /api/auth/sign-out | Server clears the session; client only reflects it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-14 | Elevation of Privilege | Client route guard as false security boundary | medium | mitigate | beforeEach is documented UX-only; every API route independently re-verifies the httpOnly session server-side (RESEARCH Responsibility Map) — no protected data is served from the client alone |
| T-02-15 | Spoofing | Logout not reaching server (client-only sign-out) | low | mitigate | Logout calls POST /api/auth/sign-out (server clears session) then routes to /login; AUTH-04 proven server-side in plan 02-04 |
</threat_model>
