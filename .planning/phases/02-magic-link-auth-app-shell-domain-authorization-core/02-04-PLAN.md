## Phase Goal

**As a** team operator, **I want to** sign in to Kurzly with a magic link and land in a themeable dashboard shell whose every domain-scoped action is authorized server-side, **so that** I can manage short links securely on my own infrastructure.

> This plan delivers the server half of the magic-link login end-to-end: it mounts better-auth into Fastify, hardens the surface (helmet + rate-limit, D-07), seeds the first admin, and proves AUTH-01..04 + the D-01 neutral response with real integration tests.

<objective>
Mount the better-auth catch-all into `buildApp()` ahead of the SPA fallback, register `@fastify/helmet` (CSP tuned for Google Fonts) and `@fastify/rate-limit` (global default + tight per-route on the magic-link request endpoint), seed the `INITIAL_ADMIN_EMAIL` user at boot so `disableSignUp` never locks it out, and prove the whole flow with `fastify.inject` integration tests.

Purpose: This is the API-side happy path for AUTH-01..04. The D-01 neutral-response canary and the seeded-admin login test are the P0 security proofs that the allowlist gate and the bootstrap path actually work (RESEARCH Open Questions 1 + Pitfall 1/A3).
Output: helmet/rate-limit plugins, the auth route, the admin seed, extended app.ts/server.ts wiring, and an auth integration suite.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/auth/* | Untrusted email + tokens; public magic-link request/verify surface |
| bot/crawler → any route | Security headers (helmet) apply to all responses |
| operator boot → DB | Admin seed writes the first privileged User row |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04 | Information Disclosure | Account enumeration via magic-link request | high | mitigate | D-01 neutral response verified by the byte-identical canary test (Task 3); allowlist gate lives inside sendMagicLink |
| T-02-05 | Denial of Service | Email-bombing / brute-force on auth endpoints | high | mitigate | @fastify/rate-limit tight per-route limit on sign-in/magic-link (Task 1/2), materially stricter than global (Pitfall 3) |
| T-02-06 | Tampering / Spoofing | Missing security headers (clickjacking/MIME-sniff) | medium | mitigate | @fastify/helmet baseline with CSP tuned for Google Fonts (Pitfall 4) |
| T-02-07 | Spoofing | Session cookie theft/fixation | high | transfer | better-auth httpOnly session cookie (secure in prod); sign-out clears server-side session — verified in Task 3 |
| T-02-08 | Elevation of Privilege | disableSignUp locks out / or auto-creates users | high | mitigate | Admin seed upserts the first User directly (Pitfall 1); disableSignUp blocks all other auto-signup; round-trip test proves both |
</threat_model>
