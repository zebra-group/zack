Per 16-RESEARCH.md Summary point 3, the rollup logic under test lives entirely in getGlobalAnalytics's raw SQL GROUP BY/JOIN scoped to `domainId IN (...)` — AnalyticsView.vue performs zero client-side summation — so proving it requires real clicks to exist across >=2 real Links (cheap: a few extra request.get calls), not a client-side reduce.

Concurrency reality (verified against lib/analytics.ts + routes/analytics.ts this research pass): getGlobalAnalytics is scoped to `scopedDomainIds(admin)` = the single baseline domain, so the global "Klicks (30 Tage)" tile sums ClickEvents across ALL links on that shared domain — concurrent specs and the db-isolation truncate churn make an EXACT global total inherently non-deterministic. The deterministic anchors are therefore (a) per-link DB counts scoped to our own linkIds and (b) the per-link "Top Links" rows scoped by our unique random slugs; the global tile is checked only with `>=` (monotonic contribution). This is 16-RESEARCH.md Open Question 2's resolution made concrete.
