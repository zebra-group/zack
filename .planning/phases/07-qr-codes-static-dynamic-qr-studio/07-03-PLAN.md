## Phase Goal

**As a** dashboard user, **I want to** create static and dynamic QR codes for my short links — with a centered logo, custom color and rounded-module styling, re-pointable dynamic targets that keep a printed code valid, and a visible scan count — **so that** I can print scannable codes that keep working even after I change where they point.

> Derived from the ROADMAP Phase 7 `**Goal:**` line into user-story shape (MVP framing).

<objective>
Build the ONE shared QR rendering core (`apps/api/src/lib/qr.ts`) — the genuinely new domain this phase introduces — test-first. This is a dedicated TDD plan because the render core has fully-defined input→output behavior (a target URL + style → a PNG/SVG that decodes back to that URL) and carries the phase's hardest blocking success criterion: the decode-round-trip for BOTH formats with a logo enabled (QR-01/QR-05). Rounded modules (QR-06) force a hand-written module-matrix renderer since node-qrcode's built-in SVG emits one combined path (RESEARCH Pitfall 2).

Purpose: A single, decode-verified renderer used by every downstream surface (thumbnail, Studio preview, PNG/SVG export) so PNG and SVG can never silently drift apart (RESEARCH Anti-Pattern: two renderers).
Output: `lib/qr.ts` exporting `buildModuleSvg`, `renderQrSvg`, `renderQrPng`, `resolveErrorCorrectionLevel`, `normalizeLogo`; a passing `qrDecode.test.ts`; logo fixtures.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-LOGO-SVG | Tampering / Information Disclosure | normalizeLogo on uploaded SVG | high | mitigate | Rasterize any SVG logo to PNG immediately on ingest via sharp; never re-parse the original SVG markup at later render time (Pitfall 5) |
| T-07-LOGO-MIME | Tampering | normalizeLogo magic-byte check | medium | mitigate | Validate actual bytes (PNG signature / SVG root), never a client-declared Content-Type, before sharp touches them |
| T-07-EC | Tampering | resolveErrorCorrectionLevel | medium | mitigate | EC level is server-forced to H when a logo is present; never read from client input, so a logo can never ship at L/M/Q and fail to scan |
| T-07-QR-PAYLOAD | Spoofing | encoded payload | low | accept | Payload is always a Link.targetUrl already validated (http(s)-only) at Link creation; the renderer never encodes a client-supplied raw URL |
</threat_model>
