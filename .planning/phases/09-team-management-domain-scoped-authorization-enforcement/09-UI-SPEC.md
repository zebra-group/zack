# Phase 09 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Deckt ab:** Genau **eine neue Route/View** (`TeamView.vue`, ersetzt den bisherigen `ComingSoonView`-Platzhalter unter `/team`) plus **ein neues Modal** (`InviteMemberModal.vue`, §8 des Handoffs) und **ein kleines Auto-Decision-Modal** (`AssignDomainsModal.vue`, für die Domain-Zuweisung an bestehende Mitglieder). Dazu zwei **strukturelle Anpassungen** an bereits gebautem UI:
- **AppShell-Nav** (`layouts/AppShell.vue`): der „Team"-Nav-Eintrag wird **admin-only** (für Mitglieder ausgeblendet, UI-09-01).
- **Router-Guard** (`router/index.ts`): die `/team`-Route bekommt `requiresAdmin` und leitet Nicht-Admins auf das Dashboard um (UI-09-01).

Die Team-View besteht aus (Reihenfolge LOCKED, Prototyp Z.366–456):
1. **Kopfzeile** — Titel „Team" + Zähler + Primärbutton „+ Mitglied einladen".
2. **Benutzer-Tabelle** (Karte) — Grid `1fr 130px 1fr 96px 28px`: Benutzer / Rolle (Select) / Domain-Zugriff (Pills) / Status (Badge) / (⋯).
3. **Rollenmodell-Hinweis** (gestrichelte Karte).

**Nicht in diesem Contract (ausdrücklich ausgeschlossen):**
- Die **„Authentifizierung"-Sektion** von §7 (Magic-Link-Karte + OIDC/SSO-Karte, Prototyp Z.413–447) — gehört zu **Phase 10**. Weder die Überschrift „Authentifizierung", noch eine der beiden Karten, noch der OIDC-Toggle/-Inputs werden in Phase 9 gebaut.
- Die Login-Preview (§9), Multi-Tenant, Per-Link-ACLs, Audit-Log, das Wieder-Versenden/Ablaufen von Einladungen aus der UI (alle laut `09-CONTEXT.md` deferred).
- Neue Design-Tokens, neue Farben, neue Schriftgrößen, neue Gewichte. `tokens.css` bleibt unverändert.

**Server-Autorität (nicht-UI, hier nur als Rahmen):** Jede in diesem Contract beschriebene Ausblendung (Nav-Eintrag, Route-Guard) ist **reine UX-Bequemlichkeit, keine Sicherheitsgrenze** — exakt wie der bestehende `requiresAuth`-Guard (T-02-14). Der Server lehnt jeden Team- und domänenfremden Zugriff serverseitig ab, unabhängig davon, was die UI anbietet (D-09-02, D-09-08). Die UI **darf** einem Mitglied die Team-Fläche schlicht nicht anbieten (`09-CONTEXT.md` §Specifics).

## Design-Fidelity Waiver / Constraint Exceptions

> **Gilt unverändert weiter (aus Phase 2 übernommen, projektweit gültig). Checker und Auditor: die unten gelisteten Phase-9-Werte sind KEINE Verstöße, sondern verbindliche, 1:1 aus dem gesperrten Prototyp extrahierte Tokens.**

### Standing Sign-Off

Requirement **UI-03**, Locked Decision **D-04 (Phase 2)**, `.claude/CLAUDE.md` („UI-Treue: High-Fidelity … pixelgenau nach Prototyp") — stehende Projekt-Owner-Freigabe für die 1:1-Reproduktion der Prototyp-Tokens. Team-Screen und Invite-Modal sind im Handoff vollständig ausmodelliert (`Kurzly Prototyp.dc.html` Z.364–456 für den Screen, Z.578–618 für das Modal; README §7 Z.96–103 und §8 Z.109–112) und werden hier unverändert übernommen.

### Ausdrücklich gewaiverte Heuristiken

1. **„Maximal 3–4 Font-Größen"** — gewaivert. Phase 9 führt **keine neue Größe** ein; jede genutzte Größe (9.5 entfällt hier, 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 15 / 16 / 21px) stammt aus der in Phase 2 gesperrten Vollskala und wird bereits an anderer Stelle im Produkt gerendert.
2. **„Maximal 2 Font-Gewichte"** — gewaivert. Phase 9 nutzt 400/500/600 aus der LOCKED Gewichts-Menge.
3. **„Alle Spacing-Werte müssen Vielfache von 4 sein"** — gewaivert. Übernommen werden die exakten Prototyp-Feinwerte (`padding:9px 16px` / `12px 16px` der Tabellenzeilen, `130px`/`96px`/`28px` Grid-Spuren, `5px 7px` des Role-Selects, `2px 8px` der Domain-Pills, `3px 9px` der Status-Badge, `padding:22px` und `1.5px`-Border des Invite-Modals).
4. **„Empty State"** — n/a mit Begründung. Die Benutzer-Tabelle ist **nie leer**: der eingeloggte Admin ist immer mindestens eine Zeile. Ein dediziertes Empty-State-Muster gibt es daher bewusst nicht (siehe Copywriting).

### Begründung

Jeder Wert stammt entweder direkt aus dem gesperrten Prototyp (Z.364–456 / Z.578–618) oder aus bereits im Code gesperrten Mustern der Phasen 3–7 (`.status-badge`, `.verify-error-row`, Delete-Dialog, `.modal-overlay`/`.modal-dialog`, Toast). Keine Ad-hoc-Erfindung.

**Accent reserved for (Phase-9-Scope) — explizite, abschließende Liste:**

1. **Primär-Aktionen (je genau eine pro Fläche):** „+ Mitglied einladen"-Button (Screen), „Magic Link senden"-Button (Invite-Modal), „Speichern"-Button (Assign-Domains-Modal).
2. **LOCKED Rollen-/Status-Signale (aus Prototyp, nicht verhandelbar):** die „alle Domains"-Pille (Admin-Zeile), die „Aktiv"-Status-Badge.
3. **Selektionszustände (Prototyp-gesperrt):** ausgewählte Rollen-Karte im Invite-Modal (Akzent-**Border** + `--chip`-Hintergrund), ausgewählte Domain-Toggle-Pillen im Invite-/Assign-Modal (Akzent-**Hintergrund** + `#1b1b18`-Text).

> **Grün (`--ok`)** wird in Phase 9 **nicht** verwendet — es gibt keine „gültig/erfolgreich"-Zählung wie im Import-Screen. Erfolg wird ausschließlich über den (neutralen, dunklen) Toast signalisiert.

**Weitere Farbfestlegungen:**
- „Ausstehend"-Badge und Mitglied-Domain-Chips sind **neutral** (`background:var(--chip); color:var(--mut)`) — Pending ist ein Zwischenzustand, kein Warn-/Fehlerzustand, daher bewusst kein Rot/Gelb.

## Interaktions- & Zustands-Contract (phasenübergreifend, verbindlich)

| Zustand | Verhalten |
|---------|-----------|
| Mitglied navigiert zu /team | Route-Guard leitet auf Dashboard um; der Nav-Eintrag war ohnehin ausgeblendet (UI-09-01). Server verweigert Team-APIs unabhängig (D-09-02). |
| Admin öffnet /team | `TeamView` lädt die Nutzerliste; jede Zeile zeigt Rolle, Domain-Zugriff, Status. |
| Rollen-Select ändern (Erfolg) | Optimistisches Update; bei Admin sofort „alle Domains"-Pille; Toast „Rolle aktualisiert". |
| Rollen-Select ändern (Fehler) | Select **revertet** auf vorherigen Wert; `.member-error-row` unter der Zeile; bei Mitglied→Admin-Revert kommen die Chips zurück (UI-09-03/04). |
| „+ zuweisen"/Domain-Chip klicken (Mitglied) | `AssignDomainsModal` öffnet, vorbelegt mit aktuellen Zuweisungen (UI-09-05/12). |
| Domains speichern (Erfolg) | Modal schließt, Chips aktualisieren, Toast „Domain-Zugriff aktualisiert". |
| ⋯ → „Mitglied entfernen" | Delete-Dialog öffnet (Surface E). |
| Entfernen bestätigen (Erfolg) | Zeile verschwindet, Toast „{email} entfernt"; Inhalt des Nutzers bleibt erhalten (D-09-06). |
| Lockout (letzter Admin, Demote/Entfernen) | Typisierter `ApiError` → Inline-Fehler (Zeile bzw. Dialog); Aktion wird nicht ausgeführt; proaktives Disable verhindert den Fall meist vorab (UI-09-07). |
| Einladen (Erfolg) | Invite-Modal schließt, neue „Ausstehend"-Zeile, Toast „Magic Link an {email} gesendet". |
| Einladen (ungültige E-Mail) | Inline-`.field-error` unter dem Input, kein Absenden (UI-09-11). |
| Pending → Active | Nach echtem Magic-Link-Login setzt der Server `emailVerified:true`; das DTO-`status`-Feld flippt auf „active". Die UI zeigt beim nächsten Laden „Aktiv" — sie re-derived nichts selbst (D-09-03/UI-09-08). |

**Fokuspunkt je Surface (Checker-Nachtrag):** Auf dem Team-Screen ist die **Benutzer-Tabelle** der visuelle Anker; Kopfzeile und Rollenmodell-Karte rahmen sie. Im Invite-Modal ist der **Rollen-Karten-Block** der Entscheidungsanker (die zwei großen klickbaren Karten), E-Mail-Feld darüber und Domain-Pillen darunter ordnen sich unter. Akzent markiert in jeder Fläche genau die eine Primär-Aktion plus die Prototyp-gesperrten Rollen-/Status-/Selektions-Signale — nichts sonst.

**Accessibility (Mindestvertrag, konsistent zu Phase 5–8):**
- Der Rollen-`<select>` ist ein natives Element — Tastatur/Screenreader-fähig ohne Zusatzaufwand; sein `disabled`-Zustand (lastAdmin) trägt einen erklärenden `title`.
- Das ⋯-Aktionsmenü ist per Tastatur erreichbar (`role="button"`, `tabindex="0"`, Enter/Space) und schließt auf Escape/Blur.
- Alle drei Modals: `@click.stop` auf dem Dialog, Klick aufs Overlay schließt, `✕` schließt; Escape schließt (konsistent mit dem bestehenden Modal-Verhalten). Der Delete-Dialog fängt den Fokus (Confirm/Cancel).
- Die Inline-Fehlerzeilen sind Text unter der jeweiligen Zeile/dem Feld; für den Rollen-Select-Fehler genügt der sichtbare, mit der Zeile assoziierte Text (keine separate Live-Region gefordert).
- Domain-Toggle-Pillen tragen `aria-pressed` (Multi-Select-Zustand); die ausgewählte Invite-Rollen-Karte trägt `aria-checked`/Radiogroup-Semantik.
