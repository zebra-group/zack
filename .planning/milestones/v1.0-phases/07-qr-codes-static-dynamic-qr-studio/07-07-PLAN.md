## Phase Goal

**As a** dashboard user, **I want to** create static and dynamic QR codes for my short links — with a centered logo, custom color and rounded-module styling, re-pointable dynamic targets that keep a printed code valid, and a visible scan count — **so that** I can print scannable codes that keep working even after I change where they point.

> Derived from the ROADMAP Phase 7 `**Goal:**` line into user-story shape (MVP framing). This plan is the first user-visible vertical slice: after it, a user can see, create, remap, and inspect QR codes in the dashboard.

<objective>
Turn `/qr-codes` from a placeholder into the live QR list surface (`QrCodesView.vue`), and lay down the single web API client layer (`api.ts`) that this view and the two following frontend plans (07-08 Studio, 07-09 Link-Detail) all consume. This is Surface A's list column + the four screen states, built to the locked UI-SPEC.

Purpose: Deliver the user-facing create/list/remap/history/scan-count capability (QR-02/QR-03/QR-04/QR-07) against the real API from 07-05.
Output: QR client functions, router swap, and QrCodesView with its states, list cards, optimistic remap, and history expander.
</objective>
