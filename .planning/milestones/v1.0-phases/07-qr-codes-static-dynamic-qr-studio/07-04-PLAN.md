## Phase Goal

**As a** dashboard user, **I want to** create static and dynamic QR codes for my short links — with a centered logo, custom color and rounded-module styling, re-pointable dynamic targets that keep a printed code valid, and a visible scan count — **so that** I can print scannable codes that keep working even after I change where they point.

> Derived from the ROADMAP Phase 7 `**Goal:**` line into user-story shape (MVP framing).

<objective>
Build the QrCode single-write-path service (`apps/api/src/lib/qrCodes.ts`) test-first, plus the shared DTOs it maps to. This mirrors `apps/api/src/lib/links.ts`'s D-01 discipline exactly: one validation gate, one create site, one update site, one remap site — no route ever calls `prisma.qrCode.*` directly. The headline correctness guarantee of the whole phase lives here: re-pointing a dynamic QR (QR-03) must never touch its printed code, and every remap records history (QR-04).

Purpose: A grep-provable single write path with a mass-assignment-safe surface and IDOR-safe domain scoping, reusing Phase 2-6 authorization verbatim.
Output: `lib/qrCodes.ts` (validate/create/update/remap/DTO/error-mapping + /q code generation), shared DTOs, and a passing integration suite including the dynamic-code-stability negative test.
</objective>
