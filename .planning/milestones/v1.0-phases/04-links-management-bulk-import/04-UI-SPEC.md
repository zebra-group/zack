# Phase 04 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Deckt ab:** Links-Screen innerhalb der bestehenden App Shell (ersetzt den `ComingSoonView`-Platzhalter für `/links`) — Links-Liste (Suche + Domain-Filter-Tabs, Tabelle mit Kurzlink/Domain/Ziel/Erstellt, Zeilen-Aktionen Kopieren/Bearbeiten/Löschen, Zeilen-Klick → Detail), Neuer-Link-Dialog (Domain-Picker nur aktive/zugängliche Domains, Ziel-URL, optionaler Slug, Validierungsfehler), Link-Detailseite (Attribute + Platzhalter-Statistik-Sektion), Einstellungen-bearbeiten-Dialog (Ziel-URL/Slug editierbar mit WARNUNG bei Slug-Änderung), Lösch-Bestätigungsdialog, CSV-Bulk-Import-Screen (Datei-Picker + Live-Validierungsvorschau „N gültig · M übersprungen" mit Zeilen-Grund), Empty State, Toast-Bestätigungen (UI-06: Erstellen/Kopieren/Import/Löschen).

**Nicht in diesem Contract:** UTM-Builder, Custom-OG-Tags, Passwortschutz, Ablaufdatum, echtes internes Klick-Tracking (Toggle + reale Zahlen), QR-Code-Erzeugung — alle diese Prototyp-Bestandteile des „Neuer Link"-Modals bzw. der Detailseite gehören zu späteren Phasen (8/6/7) und werden hier **bewusst weggelassen**, nicht nachgebaut. Die Detailseite zeigt nur eine Platzhalter-Statistik-Sektion (siehe unten).

- **Requirement UI-03** (`.planning/REQUIREMENTS.md`): „Alle Dashboard-Screens entsprechen **pixelgenau** den Design-Tokens des Prototyps (Geist-Fonts, Lime-Akzent `#d7ff01`, Spacing, Radii)."

- `.claude/CLAUDE.md` Constraint **„UI-Treue: High-Fidelity … pixelgenau nach Prototyp."**

Diese drei gesperrten Instanzen konstituieren **stehende Projekt-Owner-Freigabe** für die 1:1-Reproduktion der Prototyp-Tokens — auch für Phase 4. Keine weitere Rückfrage an den Nutzer erforderlich.

### Ausdrücklich gewaiverte Heuristiken (weiterhin gültig)

1. **„Maximal 4 Font-Größen"** — gewaivert. Diese Phase führt **keine einzige neue Font-Größe** ein — jede hier genutzte Größe stammt aus der in Phase 2 bereits gesperrten Vollskala (siehe unten, vollständig geprüft gegen Prototyp-Zeilen 61–133 und 620–777).
2. **„Maximal 2 Font-Gewichte"** — gewaivert. Diese Phase nutzt 400/500/600 aus der LOCKED Gewichts-Menge, keine neuen Gewichte.
3. **„Alle Spacing-Werte müssen Vielfache von 4 sein (4px-Grid)"** — gewaivert. Diese Phase führt Fein-Werte aus dem Prototyp fort (Grid-Gap 12px, Zeilen-Padding `11px 16px`, Header-Padding `9px 16px`, Modal-Padding 22px u.a. — siehe Spacing Scale unten) sowie zwei neue, prototyp-konform abgeleitete Struktur-Werte für Elemente, die im Prototyp so nicht existieren (Links-Tabellen-Spalten dieser Phase, Import-Screen-Panel-Breite).

### Immutable Typografie-Tokens

Diese Phase führt **keine neue Font-Größe und kein neues Font-Gewicht** ein — jedes hier verwendete Element bildet auf die in Phase 2 bereits gesperrte Vollskala ab:

### Neue, phase-4-spezifische Struktur-Werte (immutable, prototyp-/musterabgeleitet)

Identisch zu Phase 2/3: jeder Token stammt entweder direkt aus der gesperrten Prototyp-Quelle (`Kurzly Prototyp.dc.html` Zeilen 60–182, 620–778) oder — wo der Prototyp das Datenmodell dieser Phase nicht abbildet (Domain-Spalte statt Attribute/Klicks, Bearbeiten/Löschen-Aktionen, CSV-Datei-Picker statt Textarea, Skip-Gründe in der Import-Vorschau) — aus bereits gesperrten Prototyp-**Mustern** anderer Screens abgeleitet (Copy-Button-Stil, Badge-Stil, Modal-Shell, Lösch-Dialog-Shell aus Phase 3, dashed Dropzone-Konvention aus dem QR-Studio-Muster laut README). Keine Ad-hoc-Erfindung.
