## Phase Goal

**As a** team member, **I want to** create a short link by choosing a domain + destination URL (blank slug auto-generates, or I supply a custom one) and see my links listed and searchable, **so that** I can start managing short links through the one authorized creation path. (Phase 4 Success Criterion 1 + LINK-01/02/03.)

<objective>
Deliver the foundation vertical slice: the Link model applied to real Postgres via a [BLOCKING] migration, the D-01 single-write-path core (`validateLinkInput` + its three callers), and the first working capability — an authenticated member can create a link (auto or custom slug) and list/search/filter their own links.

Purpose: D-01 (bulk cannot bypass validation) is enforced structurally, not by policy: `validateLinkInput` is the sole authorization+validation gate, `createLink` is the sole insert site, and both `previewLink` (04-04 CSV preview) and `updateLink` (04-03 edit) route through the same core. Making "no bypass" a code-shape fact (one `prisma.link.create` call) lets later tests assert it directly.
Output: extended Prisma schema + migration + generated client, six shared DTOs, the `lib/links.ts` core, two rate-limit consts, POST/GET `/api/links` wired into `app.ts`, and a real-Postgres integration suite for LINK-01/02/03.
</objective>
