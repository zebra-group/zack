## Phase Goal

**As an** operator, **I want to** launch the full Kurzly stack with `docker compose up` and see the dashboard load live data from Postgres — configured only via environment variables and with data that survives restarts — **so that** I can trust the self-hosted deployment works end-to-end before enabling real features.

> This plan advances the skeleton: it delivers the UI half — an interactive dashboard that reads and writes live data through the API.

<objective>
Wire the Vue dashboard to the API (D-01 single origin): on mount it reads the live `PersistenceCanary` count from `GET /api/canary`, and a button writes a new row via `POST /api/canary` and updates the displayed count. This is the walking skeleton's real, interactive UI element wired to the API and, through it, to real Postgres — completing the operator-visible end-to-end slice.

Purpose: Prove the full stack (Vue → Fastify → Prisma → Postgres) round-trips through a real user interaction, using the shared `CanaryResult` DTO so `packages/shared` is demonstrably consumed by both apps (Pitfall 2).
Output: An interactive `App.vue` with a component test; the true browser→API→DB path is exercised by the compose smoke in plan 01-08.
</objective>
