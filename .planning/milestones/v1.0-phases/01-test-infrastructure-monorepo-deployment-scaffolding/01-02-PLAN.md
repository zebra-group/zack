## Phase Goal

**As an** operator, **I want to** launch the full Kurzly stack with `docker compose up` and see the dashboard load live data from Postgres — configured only via environment variables and with data that survives restarts — **so that** I can trust the self-hosted deployment works end-to-end before enabling real features.

> This plan advances the skeleton: it stands up the buildable monorepo every later slice depends on.

<objective>
Stand up the pnpm workspace skeleton (`apps/api`, `apps/web`, `packages/shared`), install all Phase 1 dependencies at the versions pinned in CLAUDE.md, and make `packages/shared` buildable and consumed by both apps. This is the walking-skeleton scaffold: the folders, manifests, TS config, and test-runner config every later plan builds on.

Purpose: A greenfield project has nothing installed. Everything downstream (Prisma, ENV, harness, API, Vue, Docker) needs an installed, buildable workspace with the pnpm build-script allowlist correctly set (RESEARCH Pitfall 1).
Output: A working pnpm monorepo with a committed lockfile, a buildable shared package, and base Vitest configs.
</objective>
