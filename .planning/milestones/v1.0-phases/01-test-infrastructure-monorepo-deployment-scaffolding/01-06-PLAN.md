## Phase Goal

**As an** operator, **I want to** launch the full Kurzly stack with `docker compose up` and see the dashboard load live data from Postgres — configured only via environment variables and with data that survives restarts — **so that** I can trust the self-hosted deployment works end-to-end before enabling real features.

> This plan advances the skeleton: it delivers the API half of the end-to-end path — health, SPA serving, and a real DB read/write endpoint.

<objective>
Build the Fastify application (the single-image server per D-01): a health route, the redirect-handler stub, `@fastify/static` serving the built Vue SPA with a route-order-correct SPA fallback, dev-only CORS, and the `PersistenceCanary` read/write route that is the walking skeleton's real DB round-trip. Boot is guarded by the fail-fast ENV validator from plan 01-04.

Purpose: This is the operator-visible API slice — after this plan, hitting `/health` and `/api/canary` against a running API proves the API↔DB path works end to end.
Output: A bootable Fastify app with integration tests running against the real-Postgres harness.
</objective>
