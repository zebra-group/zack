## Phase Goal

**As an** operator, **I want to** launch the full Kurzly stack with `docker compose up` and see the dashboard load live data from Postgres — configured only via environment variables and with data that survives restarts — **so that** I can trust the self-hosted deployment works end-to-end before enabling real features.

> This plan advances the skeleton: it makes the "configured only via environment variables" promise real and fail-fast.

<objective>
Build the fail-fast ENV validation module (D-06): a Zod schema parsed at boot that aborts the process with `exit 1` and a readable error on missing/invalid config, and a `.env.example` (D-07) documenting every variable — so the operator configures the instance entirely via environment variables (INFRA-02) with nothing hardcoded in the image. TDD: the validator's contract (valid → parsed, invalid → fail-closed) is written as tests first.

Purpose: Fail-closed config is an ASVS V5 input-validation control (operator-supplied env is untrusted input). A weak `BETTER_AUTH_SECRET` or missing `DATABASE_URL` must fail loudly at boot, not crash cryptically later.
Output: `env.ts` with a testable `parseEnv()` + a documented `.env.example` + a drift guard test.
</objective>
