## Phase Goal

**As an** operator, **I want to** launch the full Kurzly stack with `docker compose up` and see the dashboard load live data from Postgres — configured only via environment variables and with data that survives restarts — **so that** I can trust the self-hosted deployment works end-to-end before enabling real features.

> This plan advances the skeleton: it stands up the real-Postgres TDD harness that proves every later slice against real data.

<objective>
Stand up the real-Postgres TDD harness (D-09): a Vitest `globalSetup` that boots one shared `@testcontainers/postgresql` container, applies the committed migration to it, and provides its connection string to workers via `provide`/`inject`; plus a per-test `BEGIN`/`ROLLBACK` isolation layer. This is the VALIDATION.md "Wave 0" harness every later phase depends on. It also resolves the two flagged assumptions (A3 container-per-worker semantics, A4 transaction-rollback isolation with Prisma pooling) with early diagnostic tests.

Purpose: The project mandates TDD against real Postgres, no Prisma mocking. The harness must exist and be proven before feature work.
Output: A working testcontainers-backed Vitest harness with a green diagnostic + a green isolation canary.
</objective>
