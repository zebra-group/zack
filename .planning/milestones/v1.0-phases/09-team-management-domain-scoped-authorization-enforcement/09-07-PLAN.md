<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| modal/table input → team mutation API | Admin-typed role/domain/invite/removal actions are forwarded to authenticated, admin-gated endpoints |
| API error code → rendered message | A server error code (LAST_ADMIN, validation) selects which locked inline/dialog message is shown |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-OPT-DESYNC | Tampering | optimistic role/chip update | medium | mitigate | Every optimistic update captures the prior value and reverts BOTH role and chips on any server rejection (UI-09-03/04); tests pin the rollback so the UI never diverges from the server's actual state |
| T-09-UI-LOCKOUT | Denial of Service | last-admin disabling | medium | mitigate | Proactive client disable is UX only; the server's LAST_ADMIN guard (09-04) is authoritative and its typed error is rendered inline/in-dialog when the client guard is bypassed |
| T-09-ERR-ECHO | Information Disclosure | error rendering | low | mitigate | Messages come from fixed local constants keyed on ApiError.code (mapTeamError), never from a server-supplied string rendered into the UI |
| T-09-REINVITE-CONFUSE | Repudiation | re-invite path | low | mitigate | Re-invite shows the same success toast as a first invite (D-09-04), matching the server's indistinguishable-resend behaviour; a test asserts it is not treated as an error |
</threat_model>
