<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host test runner -> app :3000 | HTTP against the built image |
| host test runner -> db :5433 | Direct DB connection for later seed/reset |
| script env / CI env -> compose overlay | Where `E2E_RATE_LIMIT_BYPASS_SECRET` is injected |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Elevation of Privilege | `E2E_RATE_LIMIT_BYPASS_SECRET` in compose overlay | high | mitigate | Interpolated from the environment (`${E2E_RATE_LIMIT_BYPASS_SECRET}`), generated fresh per run in the script via `openssl rand -hex 32`; never a literal default in docker-compose.e2e.yml, never in the prod docker-compose.yml. |
| T-11-04 | Information Disclosure | published Postgres :5433 | medium | accept | Bound to localhost only for the test runner; the stack runs under an isolated `-p kurzly-e2e` project and is torn down with `down -v` every run. Acceptable for an ephemeral test stack. |
| T-11-05 | Denial of Service | leftover stack after a failed run | low | mitigate | `trap cleanup EXIT` always runs `down -v --remove-orphans`; the distinct `-p kurzly-e2e` project name avoids colliding with a running dev/smoke stack. |
</threat_model>
