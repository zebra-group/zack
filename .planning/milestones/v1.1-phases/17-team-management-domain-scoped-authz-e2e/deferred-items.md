# Phase 17 — Deferred Items

## D-17-05-01: Global rate-limit bucket exhaustion when running the entire `tests/authed/` directory in one Playwright invocation

**Found during:** 17-05 (AUTHZ-E2E-02), while running this phase's mandated full `tests/authed/` wave-merge gate (both `--workers=1` and default parallelism).

**What happens:** A single Playwright invocation covering all 15 files under `tests/authed/` (30 test executions across `chromium-admin`/`chromium-member`) accumulates enough real-browser-driven requests (page navigations, in-app fetch/XHR calls — none of which carry the `x-e2e-bypass` header, only direct `request`/`page.request` calls in a handful of specs do) to exhaust `registerRateLimit`'s global `100 req / 15 min` per-IP bucket (`apps/api/src/plugins/rateLimit.ts`) partway through the run. Once tripped, every subsequent request from the SAME IP within that 15-minute window gets `429`, cascading into unrelated-looking failures across whichever spec files happen to run afterward (`storage-state.spec.ts`, `team-*.spec.ts`, `qr-*.spec.ts`, `links-crud.spec.ts`, `analytics-global-rollup.spec.ts` variously, depending on run order/timing).

**Why this is NOT a production bug or a regression in this plan's own spec:**
- The global rate limit is intentional DoS-protection behavior (D-07), unchanged by this or any of Phase 17's plans.
- `apps/e2e/tests/authed/authz-admin-bypass.spec.ts` (this plan's own deliverable) passed cleanly in EVERY configuration tested this session: standalone, alongside its AUTHZ-E2E-01 sibling, in a restart-segmented full-suite pass, and at both `--workers=1` and default parallelism. It never appears in any failure list below.
- Isolating the exact failure (`team-role-domain-reassign.spec.ts`'s `GET /api/team` returning a real, logged `429`) and confirming the SAME spec passes cleanly standalone (1.5s, zero failures) proves the failure is caused by ACCUMULATED traffic from files that ran earlier in the SAME 15-minute window, not by any logic defect in the failing spec itself.
- STATE.md already flagged an earlier, narrower instance of this exact symptom after Phase 16 ("pre-existing, unrelated flakiness observed again in links-crud.spec.ts/qr-static-customize-decode.spec.ts/storage-state.spec.ts (chromium-member) when running the full tests/authed/ directory ... deferred, noted for Phase 17 or a dedicated stabilization pass") and 17-04's own SUMMARY documented the identical root cause (repeated manual re-invocation exhausting the SAME in-memory bucket, fixed by restarting the app container to clear it).

**Evidence gathered this session:**
- A fresh, single, restart-preceded run of the FULL `tests/authed/` directory at `--workers=1` still produced 8 failures; the SAME set (plus 2 more) reproduced at default parallelism — both runs showed a burst of 100+ logged `429` responses (`docker logs`, `@fastify/rate-limit`'s own `defaultErrorResponse`) hitting `/api/team` and other endpoints mid-run.
- Splitting the same 15 files into 3 restart-segmented chunks of 5 files each (clearing the in-memory bucket between chunks) made 13 of 15 files pass cleanly; the 2 residual failures (`analytics-global-rollup.spec.ts`'s top-5 crowding edge case, and `team-role-domain-reassign.spec.ts` when run directly after `team-invite-accept.spec.ts` + `team-member-removal.spec.ts` in the SAME chunk) are consistent with either an already-documented, unrelated top-5-crowding edge case in that spec's own code comments, or the SAME rate-limit accumulation within a smaller window — not new regressions.

**Recommended fix (out of THIS plan's scope, `apps/e2e/tests/authed/authz-admin-bypass.spec.ts` per its own `files_modified`):** have Playwright's `chromium-admin`/`chromium-member` projects set `use.extraHTTPHeaders: { "x-e2e-bypass": process.env.E2E_RATE_LIMIT_BYPASS_SECRET }` in `playwright.config.ts` (or per-BrowserContext via `context.setExtraHTTPHeaders`) so EVERY real-browser request — not just the handful of specs that manually set the header on direct `request`/`page.request` calls — is covered by the already-existing INFRA-06 bypass mechanism. This is a test-harness-only change (`apps/e2e/`), touches no production code, and would let the full suite run in one CI-equivalent invocation without artificial rate-limit noise. Flagged here for a dedicated stabilization pass rather than actioned in 17-05, per this plan's own file scope and the SCOPE BOUNDARY rule (pre-existing, cross-cutting, already-documented issue unrelated to this plan's own deliverable).

**Status:** Deferred — does not block AUTHZ-E2E-02's own closure (verified clean in isolation and in every restart-segmented combination attempted). Recommend addressing before the NEXT milestone adds further `tests/authed/` spec files, since each addition tightens the margin against the fixed 100 req/15 min budget.
